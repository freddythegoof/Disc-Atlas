# Apple design fixes — batch 2

October 13, 2026. Main checkout, starting from clean `7854ac3` (batch 1). Implemented findings 6 → 4 → 7 → 5 from `docs/apple-design-review.md`, plus the Directory Add bug. Findings 8–11 are untouched. No data, flight numbers, map geometry, score logic, tier/label rules or palette changed; all new motion is `transform`/`opacity` (plus `display`/`overlay` discrete holds); no new per-marker or per-frame work; no new WebGL context beyond the pop-out's existing one.

**6. Press feedback.** `public/cosmic.css` has one shared block: every tap target dips to `scale(.97)` on pointerdown (`:active`, 90 ms, expo-out) and returns on the 220 ms curve. It uses the individual `scale` property rather than `transform`, so a hover lift (a transform) stays in place under a pressed finger. Covered: the old set plus `.stack-choice`, `.directory-add`, `.inspect-disc`, the compare tray's × and Add, `.cluster-action`, `#clusterClose`, `.pick-compare`, the 3D toolbar, Enlarge, dialog `.close`, header tabs and every site, map and Add menu item. The old per-component `:active` rules (cosmic.css, directory.css) are gone. Directory rows tint (`color-mix` of the lime into the panel, 80 ms in) instead of scaling. Hover stays behind `@media(hover:hover)`. A no-op `touchstart` listener in `public/atlas-motion.js` keeps iOS Safari applying `:active`.

*Markers are a deliberate departure from the brief's wording:* the press is a GSAP tween on `.marker-stack` in `atlas-motion.js` (pointerdown, any pointer type), not CSS. A CSS `scale` there was measured to collide with GSAP, which merges the individual `scale` property into its transform: the art ended up double-scaled and stuck at .94 after release. The tween returns to the hover pose if the pointer is still over the marker, else to rest, and lets go the moment the map pans (`atlas-map.js` adds `#map.is-panning` once a drag passes its 5 px threshold; `is-dragging` is set at pointerdown, so it could not be used). A bare My Map dot (`.map-dot`, not GSAP-owned) presses via CSS at .88. The `.compare-item` card itself has no press: it is not a tap target (its × and Add are).

**4. Menu and popover exits.** `public/cosmic.css` ("Menus, popovers, dialogs…") gives every one of them the same path in and out: enter 150 ms expo-out from `scale(.96)`, exit 100 ms on `cubic-bezier(.4,0,1,1)`, transform-origin at the trigger's corner. Approach: `@starting-style` for the enter and `transition: … display allow-discrete` (plus `overlay` for popovers and dialogs) to hold the box through the exit. I did **not** use a `data-open` attribute with a `transitionend` removal: because the transition holds `display`, `hidden` / `:popover-open` still flip on the first frame, so no caller, test or `aria` logic changed. The cost is a browser dependency (Baseline 2024; see "Still verify").

- Toolbar dropdowns (`.chip-popover`) and the site menu (`.site-menu`): `[hidden]` state is the exit. Origin: `placeDropdown` (`app.js`) sets `--menu-origin` to the trigger's attached corner; the site menu defaults to top right.
- Add menu and the rack-style menu (popovers): `my-bag.css` moves `display:grid` onto `:popover-open` (the `:not(:popover-open){display:none}` that prevented any exit is removed); `positionAddMenu` (`my-bag.js`) sets the origin (left/right × top/bottom, so it grows from the corner meeting the trigger, below or above).
- Cluster popover: the `cluster-appear` keyframes (`style.css`) are replaced by the same pattern at 180/120 ms with a 6 px rise. `positionCluster` (`atlas-map.js`) sets the origin to the opening marker's centre, clamped into the popover; a marker more than 220 px from it falls back to centre, and the phone sheet rises from its bottom edge. It now reads layout size (`offsetHeight`), not `getBoundingClientRect`, since the popover is mid-scale while it enters.
- Dialogs (all but the pop-out): 150 ms in / 100 ms out, 8 px rise, with the `::backdrop` fading alongside; a closing dialog takes no pointer events.
- Menus use scale and fade only, no 4 px nudge: the Add menu's above/below placement is only known after its first style pass, so a placement-dependent translate started in the wrong direction. The corner carries the direction.
- Not changed: `.stability-popover` (a hidden-toggled tooltip not in the review's list), the filters drawer and the detail panel (GSAP slides).
- Reduced motion: the existing global `transition:none` kill makes all of it instant.

**Directory Add bug — verdict: both leads reproduced, as different symptoms.** Reproduced against unmodified code with a mocked signed-in bag API before any fix.
1. *Lead 2 (re-render detaches the trigger) — reproduced, and this is the "menu vanishes" symptom.* Open Add while the bag is still loading (or whenever the bag's colours change, which includes saving a disc): `atlas-bag-change` → `filter()` → `renderList()` replaces `#rows.innerHTML`, `placeDropdown` sees `!button.isConnected` and closes the menu a moment after it opened. Fix: `reanchorDropdown()` (`app.js`) runs after `renderList`, `updateDetail` and `renderCompare`; the open menu follows its disc to that disc's new button (and `aria-expanded` is re-asserted, which the detail panel's attribute sync was also resetting), or closes if the disc left the list. Escape then returns focus to the new button.
2. *Lead 1 (reposition on every capture-phase scroll) — reproduced, but not as a vanish.* The repositioning itself is correct. The defect: the directory's list scrolls inside its own box, and `placeDropdown` only closed when the trigger left the *viewport*. A row clipped out of the top of the list kept its menu, which then followed it up over the search and filter chips, detached from anything visible. Fix: `triggerVisible()` (`app.js`) requires 12 px of the trigger to show inside the viewport *and* every scrolling or clipping ancestor, else the menu closes. It applies to every dropdown that goes through `placeDropdown`.
No sequence of back-to-back add/save/Add rounds or scroll-first-at-once produced any other failure.

**7. Compare tray.** `renderCompare` (`app.js`) keys cards by disc id. An add inserts one card (scale .96→1 + fade, 220 ms); a remove turns the card into an inert, absolutely positioned ghost that fades and scales out over 150 ms while the survivors FLIP into the gap (transform only, 220 ms); a card whose markup is unchanged is the same node, artwork included; a hand/power/theme change replaces only the sketch `svg` (or the card, if its text changed). The tray enters with 12 px of rise and a fade over 220 ms and leaves in 150 ms, using the finding-4 pattern; an emptied tray exits *holding* its cards and the next add starts from a clean one. Reduced motion: no animation, ghosts removed at once. Not done: originating the new card from the pick button (the tray is far from the pick button on desktop and under the sheet on phones; the brief allowed skipping it). Cards still change width as the count changes (flex), so a card's width snaps while only its position glides.

**5. Pop-out.** `public/disc3d.js`, `disc3d.css`, `disc3d/viewer.mjs`. Open: the dialog is held invisible, the large viewer is created and attached (its first draw is queued by `attach`), then after one frame a WAAPI animation (`transform` + `opacity`, 320 ms, `cubic-bezier(.16,1,.3,1)`) runs from the panel stage: the dialog is scaled to fit inside the stage with its transform-origin chosen so its centre lands on the stage's centre. Close, Escape (`cancel` is intercepted), a backdrop click and the close button all run `animation.reverse()` from wherever it is, then `dialog.close()` on finish. The backdrop fades via an `.is-closing` class and a `::backdrop` transition. The panel disc turns to the dialog's pose across the exit through a new `glidePose(pose, ms)` on the viewer's own tween (tilt snaps; a flip animates), so the old snap on close is gone. A second Escape (which the browser makes uncancelable) still closes cleanly. Phones (≤700 px, touch/pen): drag the header down to dismiss (release past 22% of the screen or a fling continues the exit; less springs back); the gesture lives on the header only (`touch-action:none` there), and a long canvas drag was verified not to dismiss. `Disc3D.popoutAnimation` is exposed for tests. Reduced motion: opens and closes instantly, swipe included.

## Freddy's feel test

1. **Menus everywhere:** open and close Manufacturer, the map menu, the site (☰) menu and a directory row's Add. Each should grow a hair from the corner that touches its button (Add under a row: its top right; under a lower row, from its bottom) and leave a touch faster than it came, never blink out. Open one and press Escape, then reopen at once: it should turn around smoothly, not restart.
2. **Cluster popover and dialogs:** click a stack of discs; the popover should swell out of that marker. Close it; it fades quickly. Open Sources & method: dialog and dimming fade together; closing does the same.
3. **Directory Add sequences:** (a) Open Add the moment the page loads while signed in, before the list settles; it must stay open under the same row even if the list refreshes. (b) Save a disc to your bag, then immediately open Add on another row: always opens. (c) Open Add, then scroll the list: the menu follows its button and closes as the button slides out of the list's top or bottom; it should never sit over the search bar or chips. (d) Hammer Add/Escape/outside-click: never two menus, never a stuck-open or stuck-"expanded" button.
4. **Pop-out:** on desktop, click the 3D disc (or Enlarge): the window should open out of the panel viewer. Rotate it, then close with the ×, Esc or a backdrop click: it shrinks back into the panel and the panel's disc has already turned to match. Click ×/Esc a moment after opening: it should reverse from where it is. On a phone, drag the title row down: a long pull slides it away, a short one springs back; dragging on the disc itself only rotates it.
5. **Presses:** hold (don't release) any button, tab, menu item, chip, zoom button or cluster button: it dips about 3% immediately. Hold a directory row: it tints instead. Hold a map disc: its art dips; start dragging the map and the dip lets go. On a phone, a finger on a disc should dip it before anything opens.
6. **Compare:** add three discs: the tray rises in, each new card pops in without the others flickering. Remove the middle one: it fades where it was and its neighbours glide across. Remove the last: the tray sinks away with its card still in it. Change hand/power in the details: only the little flight lines redraw.
