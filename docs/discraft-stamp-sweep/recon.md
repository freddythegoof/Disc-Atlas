Images were inspected visually for complete artwork, contrast, foil interference and view angle. `ready` means a promising extraction candidate, **not approved or proven extracted artwork**. `risky` means Freddy should review the named concern before a later extraction attempt. `no` means the selected verified gallery source does not support the pilot bar; it is not a claim that no better photograph could ever exist.

### Source scope and limits

The source selection is the **largest usable top-face image in the product gallery**, excluding profile-only images. XL and Predator use larger frontal views from later gallery positions. Exact width/height come from the browser's decoded `naturalWidth`/`naturalHeight`; numbers across the disc are **rounded visual estimates**, not measured segmentation bounds. A 1200-pixel-wide landscape image can have only about 830 pixels across the disc; an 800×600 canvas often has just 550–650. Roughly 800 pixels across the disc is the working threshold. Reaper's approximately 750 pixels is borderline and remains risky. Large canvas dimensions alone do not prove native optical detail or an extraction will succeed.

Individual-stock photos were additionally checked for **Buzzz, Nuke, Wasp, Xpress, Stalker, Malita, Cicada and Luna**. Nuke's 12 and Luna's four offered stock originals were all measured; Buzzz and Malita were sampled. Other stock inventories, pagination and historical/sold SKU photos were **not exhaustively measured**. Therefore this is a complete mold/plastic and product-gallery recon, **not an exhaustive maximum-resolution claim over every inventory photograph on Infinite**. Each manifest entry states that scope. This limitation matters if Freddy wants a second inventory-specific source hunt before accepting a `no`.

The site remained accessible. Browsing was sequential in one tab, with normal page interactions and deliberate pacing during repeated original-image checks; no parallel crawler, hidden endpoint enumeration, anti-bot bypass or retries around a site block were used. The generic web-reading tool initially could not access the category URL; the ordinary browser loaded it and redirected to `/Brand/discraft`, with no site challenge or block observed.

Freddy clarified during recon: **require plain ESP; Signature ESP, Special Blend ESP and all other ESP-family variants keep the fallback if plain ESP is absent.** Out-of-stock plain ESP pages count as listings. The exact ESP menu item was used, not a URL guessed for a missing plastic. The stock-selection dialog can show other plastics even when opened from an ESP page; those are excluded.

## Rights and later pipeline integration

The **stamp designs are Discraft's artwork**. Rights basis supplied by Freddy: Disc Atlas holds Discraft's written permission (October 15, 2026) while the site remains a **free resource**. Infinite's photography is source evidence only: it is not licensed here, extracted as a photo texture, embedded in these docs, shipped, or displayed by Disc Atlas. The manifest records provenance URLs. Browser working views and one temporary Force download were used for inspection; no Infinite photograph is committed or retained as a project asset. Later outputs must contain **white RGB + extracted alpha artwork only**, tinted with the existing runtime ink rule; plastic colors never come from a photograph.

Read first: [pilot method and fidelity bar](../discraft-stock-stamps.md). Existing mechanism: `source-data/stamp-manifest.json` maps an exact catalog ID and mold to a local `stamps/discraft/*.png`; `prepare_data.py` validates it and emits only `stampAsset`; `validate_data.py` enforces exact manifest/catalog correspondence. The renderer gates brand and local path and keeps fallback/loading/failure behavior. This recon manifest is separate and is **not an input to the live pipeline**.

**Later-phase prerequisite:** `stamp_manifest.py` currently accepts source URLs only from `https://www.discraft.com/...`; an Infinite provenance URL would be rejected. Later approved work must explicitly extend that narrow source-host validation and its relevant tests while retaining the Discraft-only identity, rights, path and free-resource gates. Do not bypass the validator, falsify the source URL, repurpose the photo manifest, or hand-edit `public/data.json`. No such code/data changes occur in Phase A.

Per-mold fidelity remains mandatory: no reconstructed missing strokes, replacement lettering, generative cleanup or cross-mold design transfer. A player signature/emblem is retained only if that mold's own selected source has it. Zone does not acquire McBeth art from Force, Buzzz or Luna. Buzzz, Zone and Luna's existing pilot assets are not removed or replaced because their Infinite ESP candidates score `no` here.

Schema: `manifest.json` is a top-level array, one object per Infinite named entry. The requested fields are present on every object; no-ESP image fields are `null`, and `pageUrl` points to the mold page. Additive fields record inspection date, estimated disc span, flags, no-ESP plastic names, catalog matches, inventory scope and rights. `asset: null` reserves the later extracted asset path and grants no assignment approval. `otherListedPlastics` is populated for no-ESP entries only, as requested; an empty array on an ESP entry does not mean ESP is its only plastic. Catalog matches are reconnaissance evidence, never instructions to assign artwork to every listed approval.
